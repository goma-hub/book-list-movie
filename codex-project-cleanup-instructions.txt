HyperFramesの読書管理アプリ紹介動画プロジェクトを、完成品を一切変えずに整理してください。

【最優先・絶対条件】
完成動画の映像・音声・尺・画質・テロップ・タイミング・画面転換・動作・書き出し結果を変更しないこと。必要な素材、設定、コード、依存関係は削除・変更しないこと。読書管理アプリ本体は対象外です。

【作業の進め方】
1. まずAGENTS.md、HyperFrames関連Skills、package.json、README.md、video-spec.md、production-plan.md、現在のcompositions、エントリーポイントとビルド・書き出し設定を確認する。Studioでの手動編集がある場合は、Skillsに従いcatch-upを行い、変更を保持する。
2. `git status`を確認する。未コミット変更や未追跡ファイルがある場合、勝手に削除・上書きしない。作業前に現状のスナップショットを確保し、完成済みMP4は必ず保護する。履歴の書き換え、git clean、git reset --hard、強制プッシュ、リポジトリ削除は行わない。
3. 変更前に現在の動画の書き出し結果を保存・記録し、比較基準を確保する。可能なら同じ環境・設定で動画を再書き出しし、解像度・フレーム数・尺・映像フレーム・音声の一致を後で検証できるようにする。環境依存で完全一致が難しい場合は、その限界を明記する。
4. 全ファイルの参照関係を調べる。直接参照に加え、動的参照、HyperFramesの自動検出、レンダリング・CLI・Studioが使用するファイル、GitHub公開上必要なファイルも考慮する。不要と断定できる一時ファイル、古い書き出し、使われていない素材、キャッシュ、検証用出力、未使用コードを候補として分類する。
5. 削除してよいのは「生成物・一時ファイルなどで、現在の完成品の作成・再現・編集・書き出しに必要ないと確実に確認できるもの」のみ。旧素材や元の録画、代替素材、フォント、使用許諾情報、完成版MP4など、判断が分かれるものは削除せず候補として報告する。Git履歴にあるか不明な未追跡ファイルも削除しない。
6. 確実に不要なファイルだけ整理する。古いコードについては依存関係や時間設定への影響を十分検証できるものに限り、変更量を最小限にする。不確実なら変更しない。
7. README.md、video-spec.md、production-plan.mdなどを実装の現在の状態と照合し、古い構成・素材・尺・シーン・演出・BGM・コマンドの記述を、事実が確認できる範囲で修正する。AGENTS.mdはエージェント向けルールなので、不必要な重複や大幅な書き換えをしない。歴史的な制作メモや意図を無理に消さず、完成仕様と区別する。
8. .gitignoreを確認し、レンダリングキャッシュ、.transcode-cache、不要な一時出力など、再生成可能なファイルが誤って今後Git管理されないよう必要最小限で整える。ただし追跡済みファイルを勝手に除外・削除しない。
9. `npm run check`を実行し、変更前後の動画について、動画・音声・長さ・解像度・主要時点のフレームと切り替え部分を比較する。差が見つかればコードや素材の整理を元に戻し、完成品の維持を優先する。比較ができない場合は「変わっていない」と断言しない。

【禁止事項】
- 動画の演出、素材参照、テロップ、音楽、レンダリング設定、尺の最適化や改善を勝手に行うこと
- Git履歴の削除・書き換え、GitHubへのプッシュ
- 未追跡・未コミットのファイルを一括削除すること
- 依存関係が確認できないファイルを推測で削除すること
- アプリ本体を編集すること

【報告】
変更・削除したファイルを一覧にし、それぞれ理由を記載してください。削除を見送った候補も理由とともに報告してください。更新した仕様書の相違点、`npm run check`の結果、比較検証の方法と結果、未確認事項を報告してください。完成品に変化がないと検証できない場合は、変更を最小限に止めてその旨を報告してください。
